# TravelWay 上线 Supabase 云模式 · 操作指南

> 当前项目为**双模式**：未配置云 → 自动本地演示（localStorage）；配置好后 → 全站读写 Supabase，**后台修改全网立即可见**，图片直传云端 Storage。

---

## 一、30 分钟上线步骤（共 5 步）

### 第 1 步：创建 Supabase 项目（免费）
1. 打开 <https://supabase.com> → Sign in → New project
2. 填写组织/项目名（如 travelway），选择区域 **Singapore**（国内访问较快）、设数据库密码
3. 等待约 1~2 分钟初始化完成

### 第 2 步：初始化数据库
1. 左侧菜单 → **SQL Editor** → New query
2. 把项目内 `supabase/schema.sql` 全部内容粘贴进去 → **Run**
3. 看到绿色 Success 即完成（建表 + 行级安全 + 存储桶）

### 第 3 步：填入站点配置
1. 左侧菜单 → **Project Settings → API**
2. 复制 **Project URL** 和 **anon public** key
3. 打开项目根目录 `supabase-config.js`，替换成你的值：
   ```js
   window.SUPABASE_CONFIG = {
     url: 'https://你的项目.supabase.co',
     anonKey: 'eyJhbGciOi...'
   };
   ```
4. 本地预览（如 `python -m http.server 8765`）打开任意页面 → 底部出现“云模式”提示、后台登录框提示变为“邮箱登录”即成功

### 第 4 步：导入初始数据 + 创建管理员（本机执行一次）
> 需要 **service_role key**（Project Settings → API → service_role，⚠️ 等同数据库管理员权限，**只在本机用，切勿填进前端或提交代码**）

```bash
# 在项目目录（含 package.json 同级的 travel-agency/）执行，需 Node 18+
node supabase/seed-cloud.js seed  https://你的项目.supabase.co  service_role_key
node supabase/seed-cloud.js admin add https://你的项目.supabase.co  service_role_key  admin@你的域名.com 初始密码 "总管理员" admin
```

- `seed`：把本地 `data/` 的 6 条线路 / 8 个目的地 / 6 篇攻略 / 站点设置全量同步上云
  （**已上云且未被后台改过的种子数据自动跳过**，尊重云端内容，可重复执行）
- `admin add`：创建后台登录账号（Auth 邮箱 + 密码，邮箱即用户名）。想加运营账号：把末尾 `admin` 换成 `operator`

其他管理命令：
```bash
node supabase/seed-cloud.js admin list <url> <key>          # 查看管理员
node supabase/seed-cloud.js admin pwd  <url> <key> <邮箱> <新密码>
node supabase/seed-cloud.js admin rm   <url> <key> <邮箱>
```

### 第 5 步：部署上线
直接把整个 `travel-agency/` 目录拖到 **Netlify Drop**（app.netlify.com/drop）即可。
访问 `https://你的站点.netlify.app/admin.html`，用刚才创建的邮箱 + 密码登录。

## 二、云模式下行为说明

| 功能 | 行为 |
| --- | --- |
| 后台登录 | Supabase Auth 邮箱 + 密码；无“5 次锁定”（Supabase 自带限流） |
| 内容管理（线路/目的地/攻略/首页/设置） | 实时写 Supabase，前台刷新即全网生效 |
| 订单 / 留言 | 游客提交直达云端，后台实时可见；回复/改状态也落云 |
| 图片上传 | 压缩后（≤1280px）直传 Storage `images` 桶，返回公开 URL 入库 |
| 修改密码（系统设置页） | 校验旧密码后调 Supabase Auth 改密 |
| 管理员增删改（页面） | 云模式**只读**（表格下方有说明），用 `seed-cloud.js admin` 管理 —— 避免浏览器内泄露高权限操作 |
| 本地 localStorage | 云模式下不再作为数据源（仅存登录会话），切换回本地演示只需清空 `supabase-config.js` |

## 三、常见问题

- **Q：anonKey 泄露会被盗数据吗？** 不会。RLS 已开启：游客仅能读内容/提交订单留言；写内容、处理订单、改设置都需要登录且角色匹配。
- **Q：运营账号能做什么？** 后台除“系统设置 / 管理员管理”外全部可操作（内容、订单、留言、用户）。
- **Q：图片直传需要给 Storage 额外配置吗？** 不需要，schema.sql 已建 `images` 公开桶并配好策略。
- **Q：想清空云端数据重来？** 删表重建（SQL Editor 重跑 schema.sql），再执行一次 seed + admin add。
- **Q：邮箱验证？** `admin add` 默认 `email_confirm: true`，可直接登录；如用自助注册则需验证邮件。

## 四、本地开发（不配置云）

保持 `supabase-config.js` 为模板（url/key 为空）→ 全站自动走本地演示模式：
后台 `admin.html`，账号 `admin / admin123`（首次登录后建议在“系统设置 → 修改登录密码”改密）。
